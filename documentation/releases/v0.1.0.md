# v0.1.0 — Initial maintained baseline

This is the first tagged source release of the existing RWC Living Atlas. It
establishes a versioned reference for the application and its maintenance process.

## Included

- Existing React map and project-card interface, FastAPI API and PostgreSQL schema.
- Contribution guide, Bug/Feature/Maintenance Issue Forms and a PR checklist.
- Engineering CI for frontend regression/build, safe backend tests and an isolated
  PostgreSQL integration check; the existing manual validation pipeline remains.
- Roadmap, security-reporting guidance and a production operations runbook covering
  deployment records, migration preflight, backup/restore and rollback.
- A repeatable repository setup script for Issues, labels, milestones, a project
  board and main-branch rules. Running the script requires separate management
  permissions; this source release does not assert that those settings are active.
- Canonical MIT License heading. Existing license terms and the 2025 CEREO
  copyright notice are preserved.

## Verification and known limits

The automatic publisher requires a successful Engineering CI push run for the
exact current `main` commit. See that commit's Actions runs for detailed results.
The release identifies source code; record Netlify/Render deployment IDs and SHAs
separately before treating it as a deployed production version.

Production authorization/security review, representative capacity/SLO validation,
full browser journeys and backup/restore rehearsal remain roadmap work. The
October 16 manual workflow passed validation/build but failed deployment
verification/sync; inspect that path during deployment. The root `render.yaml`
is a generic Node blueprint and does not describe a verified FastAPI production
deployment. See [operations](../OPERATIONS.md) and the
[test strategy](../TEST_STRATEGY.md) for the evidence and boundaries.

## Deployment and rollback

This maintenance change introduces no production database migration or required
application environment variable. Follow [OPERATIONS.md](../OPERATIONS.md) to
identify the actual services, validate the deployed frontend/backend and manual,
and retain a compatible previous application/database recovery point.
