# 邮箱双因素认证（email two-factor authentication, 2FA）回归报告

2026-11-24。基线为 `d4043f6`，后端和前端功能修订分别为 `c86f81b` 和 `d6b30c3`。使用 FastAPI 0.95、PostgreSQL 17 的 `127.0.0.1:5433/livingatlas_test` 和 Edge。前端保持 `http://localhost:8000` 配置，浏览器测试将请求转到独立本机后端。邮件发送使用测试替身（test double），地图和其他外部请求在浏览器测试中拦截。

| 检查 | 结果 |
| --- | --- |
| 开启与关闭 | 默认关闭。缺少登录会话（session）或当前密码错误时拒绝修改。确认邮件验证码后才开启。验证当前密码后关闭，之后可只用密码登录。 |
| 登录、账号切换与会话 | 启用后，密码正确先返回 HTTP 202，未签发会话令牌（session token），也未更新时间。输错验证码返回 401。验证成功返回 200，切换账号时替换原会话。旧版登录接口无法跳过验证。 |
| 验证限制 | 验证码只能使用一次，10 分钟后过期。验证了邮件发送失败、跨账号或用途提交、限流（rate limiting）、重发沿用错误次数，以及两个并发验证请求中只签发一个会话。重置密码或关闭认证会使待验证的登录验证码失效。 |
| 浏览器（browser） | Edge 走通开启、退出、输错后改正、切换账号、关闭和恢复密码登录。390 像素宽度下验证码输入框保持可见，且设有一次性验证码自动填充属性（one-time-code autocomplete attribute）。 |
| 数据清理 | 接口测试和浏览器各使用两个合成账号（synthetic accounts）。退出前均确认对应账号、会话和验证码记录已清理。 |

从后端目录运行 `python -m scripts.check_email_two_factor` 和 `python -m scripts.check_account_recovery`。邮箱双因素认证脚本已加入 PostgreSQL 持续集成（continuous integration, CI）流程。后端离线回归 83 项全部通过，其中用户管理测试 17 项。前端 42 套测试的 274 项全部通过，其中邮箱验证码的覆盖见 `emailTwoFactor.test.js` 和 `api.session.test.js`。生产构建（production build）完成，仍报告原有静态检查警告。手册导出验证通过。

浏览器测试初次执行遇到测试脚本语法错误。下一次登录接口返回 200，但测试对含有倒计时的提示要求整句匹配，超时后改为检查真实会话状态，整个流程复测通过。临时脚本与浏览器日志在 `backend/.local-postgres/`。后端离线回归在默认沙盒（sandbox）中首次无输出，停止后以本机执行权限重跑，6.344 秒全部通过。本轮验证功能和并发请求的一次性消费。生产邮件投递和负载性能待在发布环境校验。
